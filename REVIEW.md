# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `create_employee` (lines 79-83) | Check-then-insert race condition. Uses `find_one({"emp_code": body.emp_code})` before `insert_one()`. Parallel requests can both see None and insert duplicate `emp_code` records. | Send concurrent `POST /employees` requests with identical `emp_code = "EMP0001"`. Both succeed with 201, corrupting uniqueness. | Created unique index on `{"emp_code": 1}` at startup. Wrapped `insert_one` in `try...except DuplicateKeyError`, returning 409 Conflict. |
| 2 | `punch_in` (lines 104-118) | Check-then-insert race condition. Uses `find_one({"emp_code": ..., "date": ...})` before `insert_one()`. Concurrent punch-in requests both succeed. | Send concurrent `POST /attendance/punch-in` requests with identical `emp_code` and date. Multiple attendance records are created for the same day. | Created unique compound index on `{"emp_code": 1, "date": 1}`. Atomic `insert_one` catches `DuplicateKeyError` and returns 409 Conflict. |
| 3 | `compute_late_minutes` (lines 33-37) | Grace period logic bug. Truncates minutes using `int(...)` before comparing `minutes > 10`. For shift 09:30, punch-in at 09:40:01 has elapsed time 10m 1s; `int(601 / 60)` is 10, failing `10 > 10` and returning 0. | Punch-in at 09:40:01 for a 09:30 shift. Returns 0 instead of the mandated 10 minutes (rule R2). | Checked if total elapsed seconds strictly exceeds grace period (`elapsed_seconds > 600`), then returned `int(elapsed_seconds // 60)`, else 0. |
| 4 | `compute_overtime` (lines 44-47) | Missing 30-minute minimum threshold. Overtime computed as `max(0, int(...))` without enforcing rule R3 (counted only if >= 30 minutes; otherwise 0). | Punch-out 15 minutes after shift end (e.g. 18:45 for 18:30 shift). Returns 15 instead of 0. | Checked `diff_sec >= 1800` (30 min). If true, return `int(diff_sec // 60)`, else return 0. |
| 5 | `compute_work_hours` (lines 40-41) | Banker's rounding violation. Uses Python's built-in `round(..., 2)` which performs round-half-to-even instead of round-half-up (R4). | Duration of 9.125 hours yields 9.12 instead of 9.13. | Replaced with `decimal.Decimal` and `quantize(Decimal('0.01'), rounding=ROUND_HALF_UP)`. |
| 6 | `compute_overtime` (lines 45-47) | Overnight shift end calculation failure. Instantiates shift end using `date_str` of attendance date. For overnight shifts (22:00 - 06:00), shift end falls on the next calendar day. | Punch-out at 06:40 on 2026-07-07 for a 2026-07-06 overnight shift. Yields over 1480 overtime minutes instead of 40 minutes. | Detected overnight shift (`shift_end <= shift_start`) and added 1 calendar day to shift end instant. |
| 7 | `punch_in` (lines 102-103) | Attendance date calculation ignores IST and overnight shifts. Uses `ts.date()` in local machine timezone. For overnight shifts, punch-ins before `shift_end` belong to the previous day (R1). | Punch-in at 02:00 IST on 2026-07-07 for 22:00-06:00 shift. Assigned date `2026-07-07` instead of `2026-07-06`. | Parsed instant in IST. If overnight and IST time < `shift_end`, attendance date set to previous day (`ist_date - 1`). |
| 8 | `punch_in` (line 101) | Unhandled nonexistent employee crash. If employee does not exist, `emp` is None. Accessing `emp["shift_start"]` raises `TypeError`, causing an unhandled 500 error. | Punch-in with unknown employee `EMP9999`. Server crashes with HTTP 500 instead of returning 404. | Added validation `if not emp: raise HTTPException(404, "employee not found")`. |
| 9 | `list_employees` (line 93) | Pagination off-by-one error. Calculates `skip = page * page_size`. For page 1, skip is 20, completely skipping the first 20 employees. | `GET /employees?page=1&page_size=20` returns employees 21-40; page 1 records are omitted. | Corrected skip calculation to `skip = (page - 1) * page_size`. |
| 10 | `list_employees` (line 94) | Unfiltered total count. Calls `db.employees.count_documents({})`, ignoring query filter `q`. Violates R10 ("total always reflects filters"). | `GET /employees?department=Engineering` on a DB with 5 Engineering and 30 Sales employees returns `total: 35` instead of 5. | Passed filter to count: `total = db.employees.count_documents(q)`. |
| 11 | `list_employees` (line 95) | Missing sort order. Documents returned in arbitrary natural order instead of sorted by `emp_code` ascending. | Repeated queries return employees out of alphanumeric order. | Added `.sort("emp_code", 1)` to database query. |
| 12 | `list_attendance` (lines 144-147) | In-memory sorting and scaling catastrophe. Calls `list(db.attendance_logs.find(q))` and sorts in Python. Blows up memory on 100,000 records. | Querying 100k records causes high memory spike and multi-second latency or OOM. | Replaced with database-level `.sort([("date", -1), ("emp_code", 1)]).skip(skip).limit(page_size)` backed by index. |
| 13 | `health` (lines 72-74) | Dummy readiness probe. Unconditionally returns `{"status": "ok"}` without testing database connectivity. | Stop MongoDB; `GET /health` still returns 200 OK instead of 503 Service Unavailable. | Added `client.admin.command('ping')` in try/except, returning 503 on failure. |
| 14 | `punch_in` / `list_attendance` (lines 119, 149) | Schema violation with leaked internal `id`. Inserts `"id": str(doc["_id"])` into response, which is disallowed by OpenAPI `AttendanceRecord` schema. | Schema validation against `openapi.yaml` fails on attendance responses. | Stripped `_id` and eliminated all `id` fields from attendance responses. |
| 15 | Global instant handling (lines 102, 110) | Missing sub-second truncation. Rule R1 requires instants to be truncated to whole seconds before any calculation, storage, or response. | Punched at `1783312500900` keeps milliseconds instead of truncating to whole seconds (`1783312500000`). | Truncated epoch milliseconds via `(ms // 1000) * 1000` before creating BSON datetime and returning to client. |

### Examined and determined NOT to be defects
1. **Datetime representation at the API boundary vs. database**: The API exposes epoch milliseconds as integers, while MongoDB stores BSON UTC datetimes. Converting between BSON Date and integer milliseconds at the boundary is explicitly specified in `DATA_MODEL.md` Section 1.
2. **String representations for calendar dates (`YYYY-MM-DD`) and shift times (`HH:MM`)**: Retaining these as formatted strings rather than BSON dates is intentional per `DATA_MODEL.md` Section 1 to prevent unwanted timezone conversions and preserve exact calendar dates.
